# PyQt 桌面前端

保留现有界面和操作流程，通过 HTTP 提交配置与任务，通过 WebSocket 接收进度、日志和结果。用户配置、内置提示词和业务文件读写由后端负责。

前后端使用协议版本 2。页面通过 `BackendClient` 的明确方法调用对应 HTTP 接口，例如翻译使用 `POST /api/tasks/translation`，表格翻译使用 `POST /api/tasks/table/translate`，保存使用 `POST /api/project/save`。WebSocket 业务通知使用 `{type: "notification", name: "translation.progress", data: {...}}` 等命名消息；表格通知通过 `view` 定位页面。数字事件编号仅用于前端本地 UI 通知，不跨进程发送，也不提供通用 `/api/commands` 命令入口。

更新时需要同时替换前端与后端并重启。首次连接和每次 WebSocket 重连都会通过 `/health` 校验协议版本；不兼容时显示桌面要求版本和后端实际版本，不接收旧协议的业务消息。重连仍会重试，后端更新到兼容版本后可恢复连接。

Windows 自动安装仅支持打包版本，更新 ZIP 必须同时包含 `AiNiee.exe`、前端 `_internal`、`backend/AiNieeBackend.exe` 和后端 `_internal`。安装前保存界面设置并请求本机后端关闭；更新器等待前后端及待替换文件释放后备份并替换，复制失败时回滚，保留下载包和备份以便重试。成功后自动重启前端，保留后端连接地址，由前端按原流程连接或启动后端。远程后端不会因本机更新而关闭，需要单独更新到兼容版本。安装过程写入安装目录的 `update.log`，不会覆盖 `Data`、`ProjectCache`、`Logs`、`downloads` 或改变 `portable.txt`。macOS 仍通过打开 DMG 后手动替换应用完成安装；源码运行使用 Git 更新。更新检查只跟随正式版本，不安装 Beta 预发布包。

Windows 打包还需 Rust/Cargo 和 MSVC 工具链；`Tools/pyinstall.py` 会先从 `Tools/rust_updater` 构建更新器，避免携带旧的 `updater.exe`。可单独运行 `python Tools/build_updater.py` 更新资源中的二进制。

手动导出和翻译完成后的自动导出通过 `project.export.completed` 返回完整的文件清单和报告。桌面分别提示成功、部分失败或失败，并将完整报告和逐文件错误写入前端日志，保留错误码、源文件路径等诊断信息。停止任务且未执行导出时不发送导出完成通知。

## 目录结构

```text
Frontend/
  __main__.py                  python -m Frontend 入口
  app/
    bootstrap.py               启动和依赖组装
    window.py                  主窗口和页面注册
    navigation.py              导航项目
    event_bridge.py            网络事件切换到 Qt 主线程
    backend_connection.py      健康检查、复用或启动独立后端进程
    startup_splash.py          后端连接前显示加载页，主窗口就绪后退出
    updates.py                 桌面更新流程和更新检查线程
  pages/
    workspace/                 项目启动、提取、翻译和校对
    providers/                 接口管理、模型选择和参数编辑
    prompts/                   翻译、提取提示词编辑
    settings/                  应用及文本、音频、视频、图片任务设置
    tables/                    词典、排除表和替换表
    logs/                      运行日志
  components/
    cards/                     可复用设置卡片和信息卡片
    dialogs/                   可复用对话框
    tables/                    表格控件、委托和编辑辅助
    ...                        通知、分段控件、分隔线等
  services/
    backend_client.py          HTTP 请求、WebSocket 接收和重连，不依赖 Qt
    project_state.py           项目快照合并与远端缓存/文件读取代理
    editor.py                  后端编辑规则适配和批量校验结果缓存
    backend_paths.py           查询后端的路径默认值
    protocol.py                JSON 协议常量和序列化
    public_tables.py           用户选择的词表文件导入导出
  models/                      JSON 项目/文件/条目等显示数据结构
  platform/                    原生文件对话框、macOS 集成、进程启动和启动互斥锁
  core/                        前端事件、远端配置门面、日志、路径和主题
  resources/                   图标、本地化文本、更新程序和版本信息
```

`app` 组装页面和服务；`pages` 使用通用组件、平台适配和服务；`components` 不依赖具体页面；`services` 不依赖 Qt 或页面；`core` 和 `platform` 不反向导入页面或应用层。只属于一个页面的卡片、对话框和子页面保留在对应功能目录中。

导航栏以“接口配置”分组文字开头，下方是“接口管理”及其三个接口子项；随后是“快速开始”，包含文本、图片、音频和视频翻译工作区。

“应用设置”直接显示“外观与语言”“网络与服务”“配置管理”“应用更新”四个可折叠分组，不显示顶部页标题、说明和分组快捷按钮。配置管理与应用更新默认收起；主题、主题色与服务开关保存后立即生效，界面语言重启后生效。修改自动保存，离开页面或导入导出配置前会提交尚未保存的内容；保存失败时保留编辑并提示。

“任务配置”中的“音译设置”和“视译设置”管理说话人识别、长音频切片时长与字幕导出，“图译设置”管理输出尺寸、图片翻译提示词和译图导出格式。百炼图像接口始终启用提示词自动改写，无需设置，旧配置或 API 请求中的关闭值不再生效。三页与文译设置共用页标题、分组快捷入口、可折叠卡片及保存状态提示，结果导出组默认收起。普通设置修改后自动保存到各自独立配置，切换接口不改变这些设置；未完成或无效的文本输入暂不保存，离开页面时会尝试保存并提示错误。接口管理编辑名称、地址、密钥、格式、模型、独立并发数及协议专用字段；转录、生图和任务的请求超时统一为 300 秒，不再提供编辑。语言提示、随机种子和全局补充翻译要求保留后端/API兼容及已有值，不在这些页面编辑；图片工作区也不提供补充要求输入。

转录和生图接口卡片与翻译接口一致，通过“调整参数”设置“并发任务数”；“编辑接口”仅编辑名称和连接信息。并发任务数范围为 1～64，默认 3，设为 1 时串行。每个项目独立使用此额度；转录项目内的短音频、长音频切片和视频音轨共用请求上限，长音频完成该文件的全部切片后才发送请求。图片按此额度同时处理多张。旧接口缺少配置时统一补为 3，旧音译/视译切片并发数不再使用。修改在后续提交的任务生效，已排队和运行的任务使用提交时的配置。取消后停止派发新请求，并接收保存已发送请求的结果。

“文译设置”下只保留“提取设置”和“翻译设置”，使用与媒体设置一致的分组卡片。提取页包含任务执行、提取规则、提取提示词；翻译页包含任务执行、文本处理、提示与上下文、检查与修复、结果导出。顶部按钮可定位并展开对应组，返回页面保留滚动位置和本次会话内的展开状态。普通设置修改后自动保存，离开页面前提交尚未保存的值；保存失败时保留编辑并提示。并发任务数移至每个翻译接口的“调整参数”，独立保存为 `platforms.<接口 ID>.user_thread_counts`，默认显示 `0`，说明中注明 0 表示自动设置：按接口 RPM 与响应耗时逐步调整，连续请求失败时降低并发，本地模型优先使用可用槽位。在线自动模式从最多 8 个并发起步，上限 64；手动指定正整数时使用指定值。提取与翻译使用各自绑定接口的并发数，未绑定时跟随激活接口；已有接口缺少此项时初始化为自动，旧全局并发值不再生效。修改在下次任务生效，已提交任务保持提交时的接口配置。提取批量大小与翻译的切分模式、批量大小、最大轮次仍在任务设置中管理。

“管理提示词”在当前设置页内打开提示词库，保留左侧导航位置。翻译、图片提示词和提取的基础、裁定提示词通过“新建提示词”弹窗填写名称与内容，保存后选中应用，取消不新增条目；系统预设只读，不提供“复制并编辑”，自定义项支持直接改名、编辑、保存和删除。“管理翻译指导”通过与设置页一致的胶囊按钮切换角色介绍、背景设定、翻译风格、翻译示例，标题下方说明随当前项更新。工具条参照术语表布局，不含搜索栏；各项的独立启用开关、保存和表格导入位于右侧。角色介绍的设置菜单仅含导出与重置，插入、删除行仍可使用表格右键菜单；翻译示例也在设置菜单提供行操作。保留表格排序与角色校验。提示词可点击“保存修改”，指导可点击“保存”，返回或切换时也会保存，失败则保留当前内容并阻止离开。管理页按需创建，不在应用启动时加载这些编辑器。

Python 文件和包使用小写下划线，类名保持原有命名。新增页面放入对应功能目录，在 `app/window.py` 或所属工作区页面注册；可复用控件放入 `components`，网络访问放入 `services`。

前端不导入 `Backend`，可以单独复制 `Frontend`、`AiNiee.py` 和 `requirements-frontend.txt` 部署。`core/config.py` 只访问远端配置；`models` 将 JSON 转为界面数据；`services/project_state.py` 保持显示对象身份并将编辑、搜索和校对转发到后端。业务规则只在后端执行，断线不会回退到本地配置或业务实现。

## 视频翻译

“音频翻译”之后的“视频翻译”支持拖放、文件和文件夹导入 MP4、MKV、MOV、AVI、WebM、M4V、WMV、FLV。导入阶段读取元数据，转录阶段自动选择默认音轨（没有默认音轨时取第一条），提取音频并复用长音频切片流程。Windows/macOS 自动发布包自带 FFmpeg 和 ffprobe，解压即可使用；源码运行需要自行安装这两个工具。

“校润”页显示视频画面和时间轴，当前双语字幕以白字、半透明底色叠加在画面底部，不单独占用布局空间；没有当前字幕时自动隐藏。字幕表格默认收起。点击顶部“字幕”，表格从视频区域底部以抽屉形式展开并自动暂停播放；再次点击收起，保持暂停，需要手动点击播放继续。点击字幕表格或时间轴可跳转，修改译文自动保存并同步更新画面字幕。播放所选音轨；系统无法切换音轨时自动准备单音轨预览，直接复制视频流。Windows 的视频播放器优先使用 Media Foundation；显式设置 `QT_MULTIMEDIA_PREFERRED_PLUGINS` 时遵循用户配置。无法解码时仍可编辑、保存和导出字幕。

“视译设置”独立保存说话人分离、切片时长和导出格式/内容，对应 `video_translation_settings`。共享现有转录、翻译接口，修改不会改变音频设置。默认导出 SRT 双语字幕，也支持 VTT、ASS、LRC；不导出烧录字幕的视频或配音。视频断点重试复用已完成转录；项目全部完成后重新执行转录会重新识别。

## 媒体接口与工作区

“接口管理”中的转录和生图页面按“官方接口 / 自定义接口”展示卡片。点击“添加接口”后，先填写名称并选择平台，再填写密钥等连接信息并完成创建。已有接口可从卡片菜单编辑、激活或删除；编辑时修改自动保存，未完成或无效的字段会提示修正。转录官方预设包含百炼、“火山豆包（极速）”和 MiniMax，生图官方预设包含百炼、火山 Seedream 5.0 Pro 和 Gemini 官方；Gemini 使用基地址 `https://generativelanguage.googleapis.com`、`Gemini` 格式和 `gemini-3-pro-image` 模型，各接口独立保存凭据。


转录和生图均提供 OpenAI 官方预设；两类**新建自定义接口**默认使用 `OpenAI` 协议，已有接口保存的协议保持原值。地址可填写 `https://api.openai.com`、带 `/v1` 的基地址或对应完整接口地址，兼容服务也可使用自己的域名。默认转录模型为 `whisper-1`（逐句时间戳），默认生图模型为 `gpt-image-2.5-sunburst`（上传原图到 `/v1/images/edits` 完成图片翻译）；模型名称可编辑，并发数仍通过“调整参数”保存。当前 OpenAI 图片尺寸支持 auto 和 1024x1024、1536x1024、1024x1536。

OpenAI 纯文本转录模型只返回文本时，程序会按整段音频或切片保存，并提示没有逐句时间戳。说话人分离须选用支持该功能的模型，程序不会自动更换模型。Whisper 与 GPT-4o 转录系列的官方停用日期为 2027-02-26，界面已提示这一限制。

添加 MiniMax 转录接口时，选择 MiniMax 并填写 API Key，默认地址为 `https://api.minimax.cn/v1/speech_to_text`，模型为 `asr-1.0`。激活后即可用于音频和视频转录；并发任务数仍在接口卡片的“调整参数”中设置，默认 3。程序使用非流式识别获取逐句时间戳，开启说话人识别时保留说话人标签；长音频及大小超限文件自动切片。网络中断或响应异常时不会自动重复提交付费请求。

“火山豆包（极速）”直接使用导入的本地音频。开始转录时会固定本次选择的接口，后续切换激活接口不会改变已启动的处理。图片工作区可使用百炼、火山或 Gemini 进行单步整图翻译，输出尺寸及其他任务选项仍由“图译设置”管理。

图片、音频和视频只支持媒体文件、文件夹和拖放导入，不读取 ZIP 等压缩包；目录中的不支持文件会跳过。开始导入或打开历史项目时，窗口顶部居中显示与文本翻译相同的加载提示；成功后自动消失，失败时关闭。导入期间不显示“停止导入”按钮，等待加载完成后进入项目。起始页的最近项目可双击打开。每条记录右侧的删除按钮在确认后清理该项目进度、预览、所属素材、生图及视频音轨缓存，保留外部原始文件和用户导出的文件。删除成功后列表立即更新；失败时保留条目并显示原因。

媒体项目详情分为“翻译”和“校润”两页，顶部共用返回、保存和导出操作。翻译页展示媒体项目的进度、条目或页数、文件数与本次处理用时，并集中放置流程和语言选择。校润页提供可搜索的文件树，可像文本校润页一样将分隔线拖到最左侧收起文件树，再从左边缘拖回展开；图片只展示原图与译图对照，支持缩放和刷新预览；音频将字幕表格放在时间轴上方，底部播放条展示当前文件已译/总条目数，通过字幕和时间轴定位播放。切换两页保留当前文件和未保存修改，校润编辑仍自动保存；后台处理不会切走当前页面，保存和处理成功后不保留底部提示行。媒体监控只使用本项目快照与匹配操作的阶段进度，不订阅普通文本项目的全局统计。

翻译页的“任务状态”卡片显示当前处理阶段、实时计数及停止或异常信息，替代原“待复核文件”计数。图片、音频和视频的翻译页、校润页底部均不显示运行状态行；翻译页的任务进度环仍保留。

图片校润页不显示底部状态提示，项目文件列表仅显示文件名。预览区顶部只保留一行工具条，缩放操作在左侧，刷新按钮在右侧，不再单独显示“图片预览”标题。生成进度及处理状态集中显示在翻译页的监控卡片中。

图片、音频和视频校润页的文件树支持右键“重新翻译”。图片重新生成该文件的译图，音频和视频使用该文件已有的转录字幕重新翻译；没有字幕时提示先转录。操作按文件 ID 提交，处理期间禁用重复提交，完成后刷新当前项目并保留选中文件。其他文件的译文和译图保留，单文件任务也支持停止和结果保存。多文件音视频项目的单文件重译沿用项目目标语言，更换目标语言需执行整个项目的翻译。

音频、视频文件的右键菜单还提供“重新转录”和“重新转录并翻译”，始终重新识别所选文件，也可用于尚无字幕的文件。“重新转录”成功后替换该文件的原文字幕并清空旧译文，之后可点击“重新翻译”；“重新转录并翻译”在转录成功保存后自动翻译新字幕，转录失败、取消或保存失败时不进入翻译。翻译失败时已保存的新字幕仍保留，可单独重试“重新翻译”。其他文件不受影响，处理期间三个右键操作均禁用。

“图译设置”位于“文译设置”下方、“音译设置”上方，包含“生成参数”“翻译提示词”“结果导出”三个分组。点击“管理提示词”在页内打开与文译相同的提示词编辑器，支持预设预览、搜索、弹窗新建、改名、删除与选择自定义提示词；内置预设只读，自定义内容最多 10000 字。选择后自动应用，编辑内容在点击“保存修改”、返回或切换页面时保存，失败时保留编辑。返回设置会保留滚动位置与折叠状态。图片提示词与文译提示词独立保存，在下次生成译图时生效。预设显示完整任务句，使用与文译相同的 `{source_language}`、`{target_language}` 占位符，发送前由后端替换为项目语言；原图单独提供。自定义内容整体替换系统预设，已有自定义提示词需按需补上语言占位符，切回系统预设即可恢复默认模板。

字幕格式与字幕内容由“音译设置”或“视译设置”的“结果导出”管理，图片格式由“图译设置”的“结果导出”管理，修改后自动保存。三个页面均提供独立的“输出文件名后缀”，添加在文件名末尾、扩展名前，留空不添加；音频和视频默认 `_subtitles`，图片默认 `_translated`，不允许路径分隔符及非法文件名字符。点击项目顶部的“导出结果”时读取最新设置；旧配置缺少导出项时使用 SRT 双语字幕、PNG 图片及各自的默认后缀。对应配置分别为 `audio_translation_settings.export` / `video_translation_settings.export` 的 `format/mode/suffix` 和 `image_translation_settings.export` 的 `format/suffix`，显式传入的导出参数优先。

翻译页的图片项目直接点击“生成译图”，不显示步骤选择区域。原图与单步翻译提示词一次提交给生图接口，不提供检测、识别、逐条翻译和本地回填流程。音频和视频为“转录字幕 → 翻译字幕”，可通过步骤卡片分别或组合选择执行，按钮和卡片展示当前选择及运行状态。

每次点击生成译图会发送 `regenerate=true` 重新生成所选项目，可能再次调用付费服务；预览刷新仅重新加载已有图片。音频转录发送 `retranscribe=true`，字幕翻译发送 `retranslate=true`。完成后使用项目顶部“导出结果”选择目录，格式取自任务设置。图片翻译只保留整图单步模式，不再使用指定文本替换清单或独立文字识别接口。Gemini 输出尺寸支持 `auto`、`1K`、`2K`、`4K`，不发送百炼的提示词自动改写参数；`auto` 由模型选择尺寸。


## 启动

安装前后端依赖后，在项目根目录运行以下任一命令；默认连接 `http://127.0.0.1:3389`。入口先显示加载页，再检查后端健康状态：已有服务就直接连接，本机服务未启动时自动启动独立后端进程。加载页会显示连接、等待就绪、读取配置和初始化界面的阶段，主窗口显示后自动关闭；连接失败时关闭加载页并显示错误。加载页使用短暂的独立进程，在等待后端或加载页面时保持响应。界面缩放固定使用 AUTO 跟随系统 DPI，不再读取旧配置中的手动缩放比例；日志目录统一从“运行日志”页打开。多个入口同时启动时，通过进程间锁避免重复启动：

```powershell
python AiNiee.py
python -m Frontend
```

连接单独运行的后端：

```powershell
python -m Backend --port 3389
# 在另一个终端启动桌面
python -m Frontend --backend-url http://127.0.0.1:3389
```

`AINIEE_BACKEND_URL` 可指定连接地址，`AINIEE_API_TOKEN` 指定访问令牌。只对无路径前缀的本机 HTTP 地址自动启动；远程地址、HTTPS 地址仅连接已有服务，鉴权失败或协议不兼容时不会重复启动。源码默认使用当前 Python 在独立进程中运行 `Backend` 入口；发布版默认启动随包的独立后端可执行程序，无需安装 Python。可用 `AINIEE_BACKEND_EXECUTABLE` 指定后端程序，或用 `AINIEE_BACKEND_PYTHON` 和 `AINIEE_BACKEND_DIR` 指定源码后端的解释器和目录。启动最多等待 60 秒。后端启动、运行及 Uvicorn 日志统一写入后端主日志（便携模式默认 `Logs/backend/ainiee.log`），可通过 `AINIEE_BACKEND_LOG_DIR` 指定目录；不再生成单独的启动日志。前端日志仍由前端独立记录。

前后端始终为独立进程，不提供单进程模式。关闭窗口时选择确认，会通过 FastAPI 退出接口通知后端停止任务、保存缓存并退出；选择取消则两端继续运行。请求失败时保留窗口并提示原因。仅关闭网络连接或前端异常退出不会触发后端退出。依赖安装、配置所有权及接口协议见 [后端说明](../Backend/README.md)。

连接后端期间，接口错误和任务报告中的失败详情会通过日志事件推送到“运行日志”，包含处理阶段、错误码与文件信息。无需提前打开日志页，之后进入页面也能看到已接收的近期日志，可按错误级别筛选或搜索。过长的报告会提示查看后端日志文件。

`core/resources.py` 统一定位 `Frontend/resources`，支持 `AINIEE_FRONTEND_RESOURCE_DIR` 覆盖路径和 PyInstaller 包内路径。Windows/macOS 桌面仍以根目录 `AiNiee.py` 为入口，只收集前端模块和资源并排除 `Backend`。打包脚本另行构建 `AiNieeBackend`，后端业务模块、配置模板和模型依赖只进入后端程序目录，两端使用各自的 Python 运行环境。

构建完整发布包时，先安装 `requirements-frontend.txt`、`requirements-backend.txt`、PyInstaller 6.21+，再以 `--no-deps` 安装 `requirements_no_deps.txt`。Windows 执行 `python Tools/pyinstall.py`；macOS 执行 `python Tools/pyinstall_macos.py`。Windows 发布目录包含 `AiNiee.exe`、前端 `_internal` 和 `backend` 子目录，必须整体解压。macOS 后端位于应用包的 `Contents/Helpers/AiNieeBackend.app`，通过其中的 `Contents/MacOS/AiNieeBackend` 启动；后台包不会显示额外的 Dock 图标。

打包前还需准备内置媒体工具；自动构建工作流会执行以下步骤，并按平台、架构及构建脚本缓存结果：

1. 执行 `python Tools/prepare_ffmpeg.py`，下载 `Tools/ffmpeg-source.json` 固定版本的官方源码并核对 SHA-256。
2. Windows 在 MSYS2 MINGW64（安装 `make diffutils mingw-w64-x86_64-gcc`）中执行 `bash Tools/scripts/build_ffmpeg.sh windows x86_64`。macOS 使用 Xcode 命令行工具，执行 `bash Tools/scripts/build_ffmpeg.sh macos arm64` 或 `macos x86_64`，需在对应架构机器上构建。
3. 执行 `python Tools/ffmpeg_bundle.py` 验证工具，再执行上述 PyInstaller 打包命令。缺少工具、版本不匹配或功能检查失败时，打包会失败，不生成缺少依赖的发布包。

内置 FFmpeg 8.1.3 从未修改的官方源码构建，使用静态 FFmpeg 库和系统运行库，关闭自动外部库检测、网络、GPL/nonfree 组件及 ffplay；保留音视频探测、音轨提取、重封装所需的原生编解码器与滤镜。工具、许可证、对应源码压缩包及构建说明一起放入后端包内 `media-tools` 目录。运行时按后端包的绝对路径定位工具，不依赖当前目录；仅在内置工具缺失时回退到系统 PATH。音频探测和长音频切片同样使用这一规则。

构建结束后会在临时工作目录、空 PATH 下运行打包后的 `AiNieeBackend --check-media-tools`，检查两个内置工具的版本、生成/探测测试视频并提取 16 kHz 单声道 PCM WAV。该检查不启动服务、不读取用户配置，也不访问网络；Windows ZIP 和 macOS DMG 仅在检查成功后生成。
